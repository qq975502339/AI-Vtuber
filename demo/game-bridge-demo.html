这是什么

这是“游戏 ↔ AI-Vtuber 中间层”的可交互模拟：状态机、猜字窗口、挑字策略、主播话术、协议消息，全部按设计稿跑。你可以自己发弹幕参与猜字。

这不是什么

不接真实游戏、不接真实模型、不接 TTS。它验证的是时序和交互，不是渲染效果。真实接入时，游戏通过 WebSocket 发同样的 state / ack / event，桥回同样的 action / cmd。

这一版定的规则

  • 每次猜都真落子；猜错真扣心，字飞回。
  • 同一元素观众最多 1 次（可切 2 次）；猜错扣心后主播立刻接手，不会一直让观众猜到心用完。
  • 闯关成功才进下一关；失败重玩本关。
  • 同一关连败 2 次后，下一轮改主播单人，避免卡死在重玩循环。
  • 每关 3 道释义 + 2 道出处，只从第 1~4 题里挑；同一题可以两个都有、只有一个、或都没有。第 5 题拼完直接过关，不讲。
  • 讲故事前发 cmd: pause，讲完 cmd: resume；游戏在讲解期间不重发 state。
  • 答案只留在桥本地，主播脑永远拿不到。

时间轴

窗口长度看右上角节奏档：快 6s / 标准 10s / 慢 14s；缓冲 1~3s；第二轮更短；硬截止 25s。讲解段落不设倒计时，讲完 resume。

怎么看最直观

先看 1× 的“观众猜字”，再切“纯 AI 速通”对比节奏；把策略切到“全听观众的”，会看到连续猜错、失败重玩本关。

说明：这是设计稿的可交互演示，不是最终程序。真实版本里，游戏侧还需要补 event / cmd：成功 next_level，失败 retry_level，讲解前后 pause / resume；连败保护由桥侧决定。
